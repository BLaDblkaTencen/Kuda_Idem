# Публикация на Northflank

Итог: приложение работает круглосуточно по постоянному адресу `https://….code.run`,
без вашего компьютера и туннеля. Всё живёт в одном контейнере: API, бот и экраны.

Бесплатный план Sandbox: 2 сервиса и 1 база, без засыпания, карта не нужна.
Названия кнопок в интерфейсе Northflank могут немного отличаться от написанных ниже.

## 0. Перед началом

- Код должен быть в ветке `main` на GitHub (Northflank собирает из репозитория).
- **Остановите локальный `npm run telegram`**, пока работает версия на Northflank. Один бот не может
  опрашиваться из двух мест сразу: Telegram отдаёт ошибку 409, и сообщения уходят то туда, то сюда.

## 1. Аккаунт и доступ к GitHub

1. Зарегистрируйтесь на [northflank.com](https://northflank.com) — проще всего через вход с GitHub.
2. Разрешите Northflank доступ к репозиторию `Kuda_Idem` (Account settings → Git / Integrations → GitHub).

## 2. Проект

Create project → имя `kuda-idem` → регион ближе к вам (Европа).

## 3. База данных PostgreSQL

1. В проекте: **Create → Addon → PostgreSQL**, имя `kuda-db`, бесплатные ресурсы.
2. Если есть переключатель **TLS** — оставьте как есть, подстройка ниже, в шаге 5.

## 4. Сервис

1. **Create → Service → Combined service** (сборка + запуск).
2. Репозиторий `Kuda_Idem`, ветка `main`.
3. Сборка: **Dockerfile**, путь `/Dockerfile`, контекст `/`.
4. Порты: `3000`, протокол **HTTP**, **Public** (публичный доступ). Northflank выдаст адрес вида
   `https://p01--kuda-idem--xxxx.code.run` — это и есть адрес приложения.
5. Ресурсы: бесплатный план, 1 экземпляр (не больше одного — иначе боты будут мешать друг другу).

## 5. Переменные окружения сервиса

В настройках сервиса → **Environment**:

| Переменная | Значение | Секрет |
| --- | --- | --- |
| `DATABASE_URL` | строка подключения из аддона `kuda-db` (обычно `POSTGRES_URI`; удобнее всего через «Link addon» / secret group) | да |
| `BOT_TOKEN` | токен бота из @BotFather (тот же, что в вашем `.env`) | **да** |
| `WEB_APP_URL` | публичный адрес сервиса из шага 4, без `/` в конце | нет |
| `SEED_TEST_PLACES` | `true` — пока нет реальных мест | нет |

`NODE_ENV=production` и `PORT=3000` уже заданы в Dockerfile.

**Если в логах ошибка про сертификат (`self-signed certificate`):** уберите из `DATABASE_URL`
параметр `?sslmode=...` и добавьте переменную `DATABASE_SSL=no-verify`.

## 6. Запуск и проверка

1. Сохраните — Northflank соберёт образ и запустит сервис (первая сборка — несколько минут).
2. В логах должно появиться:
   ```
   База была пустой — загружено тестовых мест: 18
   API запущен: ...
   Бот @<имя_бота> запущен
   ```
3. Откройте `https://<адрес>/api/health` — ответ `{"ok":true,"bot":true}`.

## 7. Telegram

1. @BotFather → `/mybots` → ваш бот → **Bot Settings → Configure Mini App** → адрес из шага 4.
   Он постоянный — больше менять не придётся.
2. В чате с ботом отправьте `/start`. Кнопка меню «Куда идём?» обновится сама.

## Обновления

Каждый `git push` в `main` → Northflank сам пересобирает и перезапускает сервис.
Таблицы базы обновляются автоматически при запуске (миграции).

## Если что-то не так

| Симптом | Что проверить |
| --- | --- |
| Сборка падает | Логи сборки (Build logs) — пришлите их |
| `DATABASE_URL не задан` | Шаг 5: переменная не привязана к сервису |
| Ошибка про сертификат базы | Шаг 5: `DATABASE_SSL=no-verify` и без `sslmode` |
| `другой процесс (409)` в логах | Остановите локальный `npm run telegram`; проверьте, что экземпляр один |
| Приложение открывается, но «Откройте приложение из Telegram» | Открыто в обычном браузере — так и должно быть; в Telegram войдёт |
