# Публикация на Cloudflare Workers

Итог: приложение работает круглосуточно по постоянному адресу `https://kuda-idem.<ваш-поддомен>.workers.dev`,
без вашего компьютера и туннеля. Карта не нужна.

Как устроено:
- **Экраны** Mini App — статические файлы, Cloudflare отдаёт их сам (бесплатно, без лимита запросов).
- **API и бот** — Worker (`apps/server/src/worker.ts`), 100 000 запросов в день бесплатно.
- **База** — Neon. Таблицы создаются сами при первом запросе, места из `data/places-sevastopol.csv`
  загружаются сами, вебхук бота подключается сам.

## 0. Перед началом

- **Остановите локальный `npm run telegram`.** Бот не может одновременно работать и на опросе
  (ваш компьютер), и на вебхуке (Cloudflare).
- **Для разработки заведите второго бота** в @BotFather (например, `kuda_idem_dev_bot`) и пропишите
  его токен в локальный `.env`. Опубликованный бот останется на Cloudflare. Если запустить локально
  токен опубликованного бота, сервер это заметит и бота не тронет — напишет предупреждение в консоль.
- Строка подключения Neon — без хвоста `&channel_binding=require` (оставьте `?sslmode=require`).
- Совет: в Neon ограничьте мощность базы 0,25 CU (Branches → production → Compute → Edit),
  чтобы бесплатный лимит расходовался предсказуемо.

## 1. Аккаунт Cloudflare

Зарегистрируйтесь на [dash.cloudflare.com](https://dash.cloudflare.com/sign-up) (почта и пароль) и подтвердите почту.

## 2. Вход из терминала

В папке проекта:

```bash
npx wrangler login
```

Откроется браузер — нажмите **Allow**. Это даёт `wrangler` право публиковать Worker'ы в вашем аккаунте.

## 3. Первая публикация

```bash
npm run cf:deploy
```

Команда прогонит тесты, соберёт экраны и опубликует Worker. В первый раз Cloudflare попросит
придумать поддомен `workers.dev` — например, `kuda-idem-sev`. В конце будет адрес вида
`https://kuda-idem.kuda-idem-sev.workers.dev` — это адрес приложения.

## 4. Секреты

Каждая команда попросит вставить значение (оно не появится на экране и не попадёт в Git):

```bash
npx wrangler secret put DATABASE_URL
```

→ вставьте строку подключения Neon.

```bash
npx wrangler secret put BOT_TOKEN
```

→ вставьте токен бота из @BotFather.

После каждого секрета Worker перезапускается сам.

## 5. Проверка

Откройте в браузере `https://<адрес>/api/health`. Первый запрос подготовит базу и бота
(несколько секунд), затем должно прийти:

```json
{"ok":true,"bot":true,"botMode":"webhook"}
```

В логах (dash.cloudflare.com → Workers & Pages → kuda-idem → Logs, или `npx wrangler tail`):
`Применено миграций: N` (только когда есть новые), `Вебхук бота подключён` и
`Профиль бота обновлён: …` (только когда тексты из `bot-profile.ts` изменились).
Проверить места: `https://<адрес>/api/places` — список реальных мест из таблицы.

## 6. Telegram

1. @BotFather → `/mybots` → бот → **Bot Settings → Configure Mini App → Enable Mini App** → адрес из шага 3.
   Он постоянный. Без этого ссылки-приглашения `t.me/<бот>?startapp=…` откроют чат, а не вылазку.
2. @BotFather → **Edit Bot → Edit Botpic** — аватарка (`design/bot/avatar-*.png`),
   **Edit Description Picture** — картинка в пустом чате (`design/bot/cover.png`).
3. В чате с ботом — `/start`. Кнопка меню «Куда идём?», имя, описания и команды бот выставит сам.

## Обновления

После изменений в коде:

```bash
npm run cf:deploy
```

Новые миграции базы применятся сами при первом запросе к новой версии
(после `npm run db:generate` они встраиваются в код автоматически — тест проверяет, что не забыли).

**Осторожно с удалением колонок.** Первые секунды после публикации часть запросов ещё обслуживает
старая версия. Если новая миграция удаляет колонку, которую старый код читает, эти запросы
закончатся ошибкой (так было при удалении «атмосферы» и «можно_без_заказа»). Безопаснее в два шага:
сначала опубликовать код, который колонкой больше не пользуется, а удаление колонки — следующей публикацией.
Добавлять колонки и таблицы можно сразу: старый код их просто не замечает.

После правки таблицы мест: `npm run places:build`, затем `npm run cf:deploy` — база приведётся
к таблице сама (тест не даст опубликовать, если забыть `places:build`).

## Если что-то не так

| Симптом | Что проверить |
| --- | --- |
| `{"error":"setup_failed",...}` | `DATABASE_URL`: шаг 4, строка из Neon без `channel_binding` |
| `"bot":false` | Не задан `BOT_TOKEN` (шаг 4) |
| Бот молчит на `/start` | Логи Worker'а; откройте `/api/health` ещё раз — вебхук подключается при запуске |
| Локально «Этот бот подключён к ... (опубликованная версия)» | Так и задумано: для разработки нужен отдельный бот (шаг 0) |
| Ошибка 1027 | Исчерпан дневной лимит 100 000 запросов — сбросится в 03:00 по Севастополю |

## Другой хостинг

`Dockerfile` собирает всё в один контейнер для Node.js (бот в режиме опроса) —
подойдёт для любого хостинга с Docker. Задайте переменные `DATABASE_URL`, `BOT_TOKEN`, `WEB_APP_URL`.
Места загрузятся из таблицы сами; `SEED_TEST_PLACES` не включайте — иначе к реальным местам
добавятся вымышленные тестовые.
